# 游戏 HUD

## 职责与依赖方向

HUD 是玩家与 Boss 状态的只读表现层。PlayerHealth / PlayerResources 保存真实资源并发出变化通知，
GameplayHudPresenter 绑定数据源并转发通知，GameplayHudView 更新文本、图标与数值格式。
依赖方向由 HUD 指向玩家数据接口，玩家系统不依赖具体 HUD，也不通过 UI 结算奖励。

HUD 展示备用残机，玩家内部生命总数含本体；该语义转换属于显示层，不改变死亡规则。
生命变化通知在新数值写入后发布，原有受击前通知保持其时序。分数、Bomb、火力和擦弹
沿用玩家组件提供的数据与事件，不在 HUD 中维护第二份游戏状态。

## 绑定与生命周期

Presenter 首次绑定时读取完整快照，再通过事件更新显示。玩家未就绪、禁用或销毁时显示占位；
数据源替换和 HUD 重新启用时重新绑定，解绑时移除旧事件订阅。每帧检查的是数据源身份，
不是每帧重写所有文本。关卡重开是否重置资源由游戏系统决定，HUD 反映实际状态。

## Boss 血条

BossHudPresenter / BossHudView 与玩家 HUD 共用 Canvas，但分别绑定各自数据源。
BossHealth 保存血量真值；普通扣血通过 OnHealthChanged 在一次伤害完整结算及死亡通知后刷新。
OnBarDepleted 保留旧管归零、索引尚未推进时的阶段触发语义，不作为 UI 的唯一通知来源。

数据层 RemainingBarCount 包含当前管，View 显示时扣除当前管，只显示后续管数。
因此三管血显示 2 → 1 → 0，0 代表最后一管；该显示转换不改变死亡或阶段规则。
血管数独立于行为阶段数，切管直接显示溢出伤害结算后的比例，普通受伤平滑缩短。

自动绑定监听关卡出生事件，并从存活列表补查遗漏目标；已有目标可用时保持绑定。
首次绑定读取快照，禁用或更换目标时解除订阅；死亡清零隐藏，不等待击破演出销毁对象。
关卡重开当帧跳过旧对象补查，避免重新绑定等待延迟销毁的 Boss。
自动目标模式另比较血量快照作为兜底，仅变化时刷新；指定 Boss 模式使用事件更新。
HUD 不负责恢复 Boss 血量，也不改变对象的销毁或复用流程。

## 布局与编辑边界

CanvasScaler 负责缩放，RectTransform 负责位置、尺寸与锚点。GameplayViewportLayout
虽然保留现有类型名，但只保存编辑入口引用，没有运行时重排、相机控制或世界范围计算。
HUD 布局窗口只修改选中 UI 的 RectTransform，使用 LayoutRoot 实际 UI 坐标，保留锚点，
支持 Undo、场景 dirty 与 prefab override。编辑器代码位于 Editor 目录。

HUD 不修改战斗相机、背景相机、玩家移动边界、子弹回收区或对话布局，不决定暂停、失败、
开局重置或存档流程。进入 Play 不应触发布局脚本的另一套坐标计算；不同分辨率的变化
应由 Unity 原生 CanvasScaler 和锚点解释。

## 扩展契约

更换皮肤、调整排版、增加显示开关或提示动画，优先在 View 与 UI 资产侧扩展。
例如新增最高分显示，先由存档或计分系统提供只读数据与通知，Presenter 负责绑定，View 负责格式化；
不要在文本刷新回调中写存档或重算分数。未来编辑预览数值也应只驱动显示，不写玩家资源。

当前已实现分数、备用残机、Bomb、Power、Graze、Boss 血条及纯 UI 布局窗口。
编辑预览数值、统一显示开关、玩家数值变化动画与最高分存档尚未实现。
暂停、Game Over 等应按各自系统的状态接口接入独立界面，不把流程逻辑堆入侧栏。

配置、场景接入与美化见 [HUD 操作说明](../../Assets/Scripts/UI/README.md)。
