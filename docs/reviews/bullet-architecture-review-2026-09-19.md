# 弹幕架构评价报告

评估日期：2026-09-19。范围：当前工作区的子弹生成、发射配置、运行状态、组合、碰撞回收及相关调用方。
这是静态代码评价，不是整款游戏完成度或性能认证；评估包含尚未提交的组合调度改动。

## 结论

架构具备制作东方风格 STG 关卡和符卡的基础，值得继续建设，无需整体重写。
它已从功能原型进入需要统一行为契约的阶段：模块划分合理，但部分入口仍使用旧语义，测试和文档曾落后于实现。
建议继续做内容验证，同时优先完成状态归属、抽样与统计闭环，再用性能证据决定更深层优化。

## 已形成的优势

- 发射时机、弹幕几何、方向扩展和出生后行为分离，新玩法有明确扩展入口。
- 按 prefab 分池，复用时恢复基准缩放、视觉属性、雾化和擦弹状态；回收有活跃成员保护。
- 碰撞队列记录发射版本，降低全屏消弹与立即复用导致误回收的风险。
- FireAction 可持有独立计数与扩展实例；内置累加扩展具备状态重置与策略深拷贝。
- Composite 子项经过统一调度，路径保护允许重复引用并阻止递归环。
- 批次准备与逐弹求值分离，逐弹角度偏移已有真实调用链。
- 发射计时保留余量且限制单帧补发，暂停和零间隔分裂有防护。

## 风险与证据

| 优先级 | 当前事实与证据 | 实际影响 | 建议 |
|---|---|---|---|
| 高 | 玩家、子机、FirePatternBulletModifier 仍调用无上下文 FireGroup | 同资产累加角度仍可能跨发射器耦合 | 统一为发射口/母弹上下文，共享行为显式选择 |
| 高 | AngleOffsetFirePatternBulletExtra.OnBatchFire 的标记持续保留；池只扫描 extras 首项 | 跨批随机值可能固定，默认 Modifier 不在同一准备链 | 使用批次数据对象，覆盖所有相关模块并保持模板只读 |
| 高 | BossShotCounter 的提交入口未检查发射者 | 玩家或普通敌人可能推进 Boss 发射次数信号 | 定义统计范围并传递归属，区分根弹与分裂弹 |
| 中 | ShooterPhase 退出调用 ForceExit 后丢弃 runtime，未调用其 Dispose | 克隆 Flow 的释放没有闭环；ResetOnEnter=false 也未真正恢复旧运行 | 明确阶段恢复语义并统一释放 |
| 中 | GetRuntimeExtensions 每次生成数组；GetRuntimeFireCounts 每次生成字典；逐弹合并 Modifier 仍分配 | 高频发射和分裂会产生 GC 压力 | 缓存已准备的配置计划，按实测优化，先不池化所有模块 |

| 中 | Time.deltaTime 与 Unity 全局随机仍参与模拟 | 发射数量改进不等于确定性回放 | 有回放需求时统一步进、随机源及输入录制 |

## 配置可预测性

当前重复 Composite 子项共享同一上下文并连续推进，父配置不继承，只有根音效执行。
这套规则可以成立，关键是内容作者必须能预期；不能同时承诺每槽独立或父字段自动传递。
FireAction 重入会清零，因此旧测试弹幕可能与改动前跨 Action 累加的轨迹不同。
资产字段保留不代表行为完全兼容，应通过代表符卡对照确认。

## 验证现状

上一批完成运行时代码和弹幕 Editor/测试源的独立 C# 编译、diff 格式检查。
用户表示第一阶段基本验收完成；最新组合、统计和逐弹解析的 Unity Test Runner 执行与游戏内验收尚无结果证据。
现有测试覆盖计时、池复用、延迟回收版本、克隆、配置计数与部分角度计算，
但不能替代根到叶的集成验证。尤其仍需双 FireAction 交错发射、实际子弹角度、音效次数、统计归属和异常重入测试。
无 Profiler 基线，因此不给出稳定弹量、零 GC 或固定 FPS 保证。
本次同步仅改文档，不重新宣称 Unity 编译或运行通过。

## 推荐改进顺序及验收

1. 补端到端回归：两发射器交错、Composite 重复与循环、缺 prefab、根音效与实际弹数、异常后恢复上下文。
2. 完成统一状态归属和批次抽样：玩家/子机/母弹不互相改写模板，同批共享、跨批重新抽样均由测试确认。
3. 修统计范围和阶段释放：玩家射击不推进 Boss 专属信号，多次进出阶段不积累克隆 Flow。
4. 做三类符卡压力基线：普通密集环、多 Modifier、持续分裂；记录帧时间、GC、材质数与出弹/消弹峰值。
5. 按数据缓存数组和映射、优化材质与预热。只有瓶颈证据充分才考虑集中更新或更换渲染方案。

评价：这是可以维护、具备表达能力的模块化基础，但“所有发射器隔离、所有模板只读、统计严格归属、性能已验证”仍不是当前事实。
